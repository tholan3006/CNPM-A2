\section{Tổng quan Bối cảnh, Phân công Nhiệm vụ và Đặc tả Yêu cầu Bảo mật}

\subsection{Bối cảnh Phân hệ Đăng nhập \& Đăng ký (JWT) trong Đồ án BrewLite}
Trong kiến trúc hệ thống đặt đồ uống không tiền mặt \textbf{BrewLite}, phân hệ \textbf{"Đăng nhập \& Đăng ký"} do \textbf{Nguyễn Hữu Chí Công (Thành viên 5)} phụ trách đóng vai trò là lớp kiểm soát định danh và bảo mật trung tâm (\textit{Identity \& Access Management Layer}):
\begin{itemize}
    \item \textbf{Xác thực định danh đơn hàng và giao dịch tài chính:} Mọi thao tác tạo đơn hàng (\texttt{POST /orders}) và thanh toán không tiền mặt (\texttt{POST /payments}) đều bắt buộc gắn với định danh \texttt{userId} hợp lệ được trích xuất từ chữ ký số \texttt{JWT Access Token}, ngăn chặn triệt để các yêu cầu giả mạo hoặc đặt đơn nặc danh.
    \item \textbf{Bảo mật mật khẩu một chiều với Bcrypt:} Mật khẩu người dùng tuyệt đối không lưu dưới dạng văn bản thuần (plaintext) mà được băm một chiều bằng thuật toán \texttt{bcrypt} với hệ số chi phí \textbf{Salt Rounds = 10}, chống lại các cuộc tấn công Rainbow Table và Timing Attack.
    \item \textbf{Phân quyền theo vai trò (RBAC) và Tích điểm thành viên:} Hỗ trợ 3 vai trò (\texttt{CUSTOMER}, \texttt{BARISTA}, \texttt{ADMIN}), tự động điều hướng nhân viên pha chế tới màn hình quản lý đơn (\texttt{/orders}) và quản lý điểm thưởng tích lũy (\texttt{loyaltyPoints}) cho khách hàng.
    \item \textbf{Chuẩn hóa Đóng gói Docker \& Đường ống CI/CD:} Thiết lập cấu hình \texttt{docker-compose.yml} (3 containers: PostgreSQL, NestJS API, Next.js Web), \texttt{Dockerfile} multi-stage build, kiểm tra tự động qua \texttt{GitHub Actions CI} và quản lý an toàn khóa bí mật \texttt{JWT\_SECRET}.
\end{itemize}

\subsection{Đặc tả Yêu cầu Phi chức năng (Non-Functional Requirements: JWT \& Bcrypt)}
Bảng~\ref{tab:nfr_auth} đặc tả các yêu cầu phi chức năng cốt lõi về bảo mật và vận hành do Thành viên 5 phụ trách:

\begin{table}[H]
\centering
\small
\begin{tabularx}{\textwidth}{|c|p{3.2cm}|X|}
\hline
\textbf{Mã NFR} & \textbf{Tên yêu cầu} & \textbf{Đặc tả Kỹ thuật \& Tiêu chí Nghiệm thu} \\ \hline
\textbf{NFR-SEC-01} & \textbf{Băm mật khẩu một chiều với Bcrypt} & 
$\bullet$~Không lưu mật khẩu dạng plaintext trong CSDL hoặc log hệ thống. \newline
$\bullet$~Sử dụng \texttt{bcrypt.hash(password, 10)} với \textbf{Salt Rounds = 10} (\texttt{\$2b\$10\$...}). \newline
$\bullet$~Đối chiếu mật khẩu bằng hàm \texttt{bcrypt.compare()} chống tấn công thời gian (Timing Attack). \newline
$\bullet$~Loại bỏ tuyệt đối trường \texttt{passwordHash} khỏi mọi phản hồi JSON trả về Client. \\ \hline
\textbf{NFR-SEC-02} & \textbf{Xác thực phi trạng thái bằng JWT} & 
$\bullet$~Ký số bằng thuật toán \textbf{HMAC-SHA256 (HS256)} thông qua \texttt{@nestjs/jwt} với khóa bí mật nạp từ \texttt{JWT\_SECRET}. \newline
$\bullet$~Payload chuẩn gồm \texttt{\{ sub: user.id, email: user.email, role: user.role \}}, thời hạn \texttt{7d}. \newline
$\bullet$~\texttt{JwtStrategy.validate()} kiểm tra chữ ký số, hạn sử dụng và truy vấn đối chiếu sự tồn tại của \texttt{user.id} trong PostgreSQL. \\ \hline
\textbf{NFR-SEC-03} & \textbf{Bảo vệ Route nhạy cảm \& RBAC} & 
$\bullet$~\texttt{JwtAuthGuard} chặn 100\% truy cập không có Bearer Token hợp lệ vào \texttt{GET /auth/me}, \texttt{POST /orders}, \texttt{POST /payments} (trả về \texttt{401 Unauthorized}). \newline
$\bullet$~\texttt{RolesGuard} kiểm soát phân quyền 3 vai trò: \texttt{CUSTOMER}, \texttt{BARISTA}, \texttt{ADMIN}. \\ \hline
\textbf{NFR-VAL-04} & \textbf{Kiểm tra dữ liệu đầu vào 2 lớp} & 
$\bullet$~Frontend (\texttt{AuthModal.tsx}): Chặn phím chữ trên ô Số điện thoại (\texttt{handlePhoneKeyDown}), bắt buộc đúng 10 chữ số. \newline
$\bullet$~Backend (\texttt{ValidationPipe}): Kiểm tra \texttt{@IsEmail()}, \texttt{@MinLength(6)}, chuẩn hóa \texttt{email.trim().toLowerCase()}. \\ \hline
\textbf{NFR-DEP-05} & \textbf{CI/CD, SSL/HTTPS \& Secrets Vault} & 
$\bullet$~Hàm \texttt{getJwtSecret()} kiểm tra nghiêm ngặt biến môi trường \texttt{JWT\_SECRET} khi khởi động (Fail-fast). \newline
$\bullet$~Đường ống GitHub Actions CI tự động build \& test; triển khai đồng bộ qua \texttt{docker-compose.yml} và mã hóa HTTPS/TLS 1.3. \\ \hline
\end{tabularx}

\label{tab:nfr_auth}
\end{table}

\subsection{Hiện thực Backend API Auth JWT \& Mã hóa Bcrypt (\texttt{auth.service.ts} \& \texttt{jwt.strategy.ts})}
Dịch vụ \texttt{AuthService} thực hiện chuẩn hóa email, kiểm tra trùng lặp, băm mật khẩu một chiều bằng \texttt{bcrypt} với \texttt{Salt Rounds = 10}, đối chiếu mật khẩu an toàn và ký phát hành \texttt{JWT Access Token}:

\begin{lstlisting}[caption={Hiện thực đăng ký, băm mật khẩu Bcrypt và đăng nhập JWT tại AuthService}]
@Injectable()
export class AuthService {
  constructor(
    private readonly prisma: PrismaService,
    private readonly jwtService: JwtService,
  ) {}

  async register(dto: RegisterDto) {
    const normalizedEmail = dto.email.trim().toLowerCase();
    const existingUser = await this.prisma.user.findUnique({
      where: { email: normalizedEmail },
    });
    if (existingUser) {
      throw new ConflictException('Email is already registered');
    }

    const passwordHash = await bcrypt.hash(dto.password, 10);
    const user = await this.prisma.user.create({
      data: {
        email: normalizedEmail,
        passwordHash,
        fullName: dto.fullName?.trim() ?? null,
        phone: dto.phone?.trim() ?? null,
      },
    });

    const payload = { sub: user.id, email: user.email, role: user.role };
    const access_token = await this.jwtService.signAsync(payload);

    return {
      access_token,
      accessToken: access_token,
      user: {
        id: user.id,
        email: user.email,
        fullName: user.fullName,
        phone: user.phone,
        role: user.role,
        loyaltyPoints: user.loyaltyPoints,
      },
    };
  }
}
\end{lstlisting}

\subsection{Hiện thực Giao diện Đăng nhập / Đăng ký (\texttt{AuthModal.tsx})}
Màn hình hộp thoại \nolinkurl{apps/web/src/components/AuthModal.tsx} trên Next.js 14 kiểm tra định dạng số điện thoại 10 chữ số theo thời gian thực, gọi API xác thực, lưu JWT vào \texttt{cartStore} và tự động điều hướng theo vai trò:
